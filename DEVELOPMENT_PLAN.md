# План разработки RAG-системы на базе SmartChanker

## Обзор проекта

RAG-система для работы с документами, использующая интеллектуальный чанкер SmartChanker для создания структурированных чанков с сохранением иерархической структуры документов.

## Технологический стек

### Реализовано

- **Чанкер**: SmartChanker (https://github.com/igorvolk1961/smart_chanker)
- **RAG Framework**: LlamaIndex
- **Векторное хранилище**: Qdrant (с абстракцией через VectorStoreInterface)
- **Эмбеддинги**: GigaEmbeddings (GigaChat API) - основной эмбеддер
- **LLM**: Поддержка любых провайдеров с OpenAI-совместимым API (OpenAI, Ollama и другие)
- **Backend**: FastAPI
- **Desktop App**: Tkinter (для отладки в автономном режиме)
- **Веб-поиск**: Tavily API
- **Реранкинг**: Через внешние LLM API запросы

### Архитектурные решения

- **Абстракция от БД**: `VectorStoreInterface` + `QdrantAdapter` для возможности замены векторной БД
- **ChunkRepository**: Репозиторий для работы с чанками через абстрактный интерфейс
- **Система агентов**: Гибкая система с инструментами для RAG, веб-поиска и рассуждений
- **Кэширование конфигураций**: Кэширование LLM, эмбеддингов и других конфигураций по ключам подключения

## Текущие проблемы и известные ограничения

### Критичные проблемы

#### 1. Проблема с гибридным поиском

**Проблема**: Полнотекстовый поиск в гибридном режиме не возвращает результатов, что снижает эффективность гибридного поиска.

**Описание**:
- В примерах использования полнотекстовый поиск не дает ни одного чанка
- Возможно, есть ошибка в реализации `_text_search` или `_text_search_fallback` в `rag/retriever.py`
- Необходимо проверить корректность работы полнотекстового поиска Qdrant и индексации текста

**Статус**: Требует диагностики и исправления

**См. также**: [TODO.md](TODO.md) - раздел "1. Проблема с гибридным поиском"

### Архитектурные улучшения

#### 2. Интеграция ElasticSearch для полнотекстового поиска

**Проблема**: Текущая реализация полнотекстового поиска через Qdrant может быть недостаточно эффективной.

**Описание**:
- В файловом хранилище КФО уже реализован ElasticSearch для полнотекстового поиска
- Необходимо рассмотреть возможность использования этого решения для улучшения качества поиска
- Это может улучшить интеграцию с существующей инфраструктурой

**Статус**: Требует исследования и оценки

**См. также**: [TODO.md](TODO.md) - раздел "2. Интеграция ElasticSearch для полнотекстового поиска"

#### 3. Абстракция эмбеддера от GigaEmbeddings

**Проблема**: Текущая реализация жестко привязана к GigaEmbeddings, что ограничивает гибкость системы.

**Описание**:
- Система использует `GigaEmbedding` напрямую без абстракции
- Нет абстрактного интерфейса для эмбеддеров (аналогично `VectorStoreInterface`)
- Это затрудняет использование других эмбеддеров (Ollama, OpenAI и др.)

**Статус**: Планируется для улучшения архитектуры

**См. также**: [TODO.md](TODO.md) - раздел "3. Абстракция эмбеддера от GigaEmbeddings"

### Улучшение качества

#### 4. Переработка системного промпта для комбинированного поиска

**Проблема**: Системный промпт для комбинированного поиска (интернет + база знаний) может быть неоптимальным.

**Описание**:
- Текущий промпт в `api/agents/prompts/combined.txt` может не эффективно координировать использование обоих источников
- Необходимо улучшить логику выбора между интернетом и базой знаний
- Улучшить синтез информации из разных источников

**Статус**: Требует анализа и переработки
